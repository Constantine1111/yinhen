## 三、核心机制（改动前必读）

1. **导出管线**：选图（最多 20 张批量）→ EXIF 解析（缺参数可手填兜底）→ 画布排版 → 导出（完整继承原片 EXIF、HDR 重组、最高 4096px、六档画幅中心裁切）→ 成功后 `ProfileStore.recordExport`。
2. **档案与成就流**：`recordExport` → `applyRecord`（聚合统计）→ `judgeAchievements`（判定）→ save；解锁成就进弹窗队列（`enqueueAchievementCard` → `pumpAchQueue`），**同一天最多弹 3 次**，3 秒自动收起。
3. **防作弊红线**：品牌/镜头/参数成就只认 `exifNative = true`（EXIF 解析器原生输出）的记录，手动输入一律不参与判定；导出失败不记录。**此设计不可破坏。**
4. **成就徽章**：38 张 512×512 透明蚀刻章（源：`G:\AI工作区\0 蚀刻章\normalized2`），经 `ACH_BADGES` Record 映射到 `$r('app.media.badge_xxx')`；隐藏成就用 `badge_hidden.png` 灰色六边形 + 半角 `???` 占位（全角？墨迹偏左，见踩坑 #3）。
5. **成就现况**：总数 38（v1.0.6 新增入门成就：初见海面/熟手/一周之约/第一个标签/参数党）；品牌梗门槛为累计 5 张；参数党不回溯历史导出；十项全能按已解锁数 ≥10 判定。
6. **导航**：底部悬浮胶囊（沉浸光感材质、滚动隐藏、衬底明暗自适应）；「我的」页内三分段：统计｜成就墙｜设置。

## 四、构建、签名与发布

### 日常开发
- 构建：`devecocli build`（debug）；部署：`devecocli run --skip-build --device <serial>`（设备串号先用 `devecocli device list` 查，模拟器端口会变）
- `.ets` 改动后先跑一次 `arkts_check`，再 build
- 模拟器安装报 `code:9568332`（sign info inconsistent）→ `devecocli run --uninstall --skip-build`

### Release 构建
- hap：`devecocli build --build-mode release` → `entry/build/default/outputs/default/entry-default-unsigned.hap`（+signed 为 debug 证书签的名，AGC 不认）
- .app：`hvigorw assembleApp --mode project -p product=default -p buildMode=release` → `build/outputs/default/yinhen-default-unsigned.app`
  - 项目根目录没有 hvigorw 包装脚本，直接调用 DevEco 自带的 `& "D:\Program Files\Huawei\DevEco Studio\tools\hvigor\bin\hvigorw.bat"`
  - 前置环境：`DEVECO_SDK_HOME=D:\Program Files\Huawei\DevEco Studio\sdk`，PATH 加 `...\jbr\bin`（缺 java 会 `spawn java ENOENT`）
  - 改过环境变量后必须 `hvigorw --stop-daemon` 再跑（守护进程缓存旧环境）

### 签名体系（关键！）
- **开发签名**：DevEco 自动 debug 签名（`build-profile.json5` 的 `default` 配置，口令为 DevEco 加密串，随仓库提交无碍）
- **发布签名**：AGC 发布证书 `E:\yinhen_key\yinhen1.cer` + 发布 Profile `yinhen1Release.p7b` + 密钥库 `yinhen.p12`（keyAlias `yinhen`）。**口令由作者持有，历来口头提供；严禁写入任何文件或仓库。**
- **hvigor 6.x 陷阱**：`signingConfigs` 不接受明文口令（报「length less than 32」，要求 DevEco 加密格式）→ 发布签名绕过 hvigor，用官方 hap-sign-tool 直签：
  ```
  java -jar "<DevEco>\sdk\default\openharmony\toolchains\lib\hap-sign-tool.jar" sign-app ^
    -mode localSign -keyAlias yinhen -appCertFile E:\yinhen_key\yinhen1.cer ^
    -profileFile E:\yinhen_key\yinhen1Release.p7b -signAlg SHA256withECDSA ^
    -keystoreFile E:\yinhen_key\yinhen.p12 -keyPwd <口令> -keystorePwd <口令> ^
    -inFile <unsigned.hap 或 unsigned.app> -outFile <signed> -compatibleVersion 26
  ```
  （java 用 `<DevEco>\jbr\bin\java.exe`）
- **校验**：同工具 `verify-app -inFile <signed> -outCertChain x.cer -outProfile x.p7b`，Verify success 且提取的 profile 与 `yinhen1Release.p7b` 哈希一致即为发布签名
- **.app 包结构**：外层整包签名 + 内层 hap **不签名**（v1.0.5/v1.0.6 均此形态，AGC 接受）；GitHub 不允许 .app 附件 → 直接改名加 `.zip` 后缀上传（不压缩）
- **AGC 报「软件包解析失败」** ⇒ 几乎必是 debug 证书签名所致，用上述流程以发布证书重签后再传

### 版本发布检查清单（每次发版照此执行）
1. 功能收尾：`arkts_check` → `devecocli build` → 模拟器 `devecocli run` 冒烟
2. 升版本号：`AppScope/app.json5`
3. 定稿 `总结/版本更新日志.md`：「下一版本（待发布）」小节改为 `vX.Y.Z（日期）` 并补全内容，再新开空的「下一版本」小节
4. 构建 release hap + .app → hap-sign-tool 发布签名 → verify-app 校验
5. `发布/` 留副本：`yinhen-vX.Y.Z-release.hap / .app / .app.zip`
6. git：提交「印痕 vX.Y.Z」→ push → 打 tag `vX.Y.Z` → push tag
7. GitHub Release：标题「印痕 vX.Y.Z」，正文取更新日志该版本小节 + 尾注（完整日志链接、.zip 说明），上传 .hap 与 .app.zip，置 Latest
8. AGC：上传发布签名的 .app；版本说明文案可参考 v1.0.6（AppStore 模板：新增功能 + 优化 + 联系方式）
9. **回到本文件**：更新里程碑表、补充本版本成果与新踩坑

## 五、踩坑记录（现象 → 原因 → 解法）

1. **安装报 code:9568332 sign info inconsistent** → 设备上残留旧签名包 → `devecocli run --uninstall --skip-build`
2. **模拟器连不上/串号变了**（5555→5557）→ 模拟器重启后端口漂移 → 先 `devecocli device list`
3. **隐藏成就名「？？？」视觉偏左** → 全角「？」墨迹在字身框内偏左约 7%（CJK 标点惯例）→ 改半角 `???` 即居中
4. **Path 绘制的六边形占位偏小且缩在左上** → ArkUI Path 链式 `.width()/.height()` 不缩放绘制坐标（viewport 缩放陷阱）→ 放弃代码绘制，改用 PNG 资源 `badge_hidden.png` 走统一 Image 管线
5. **徽章图源取舍** → 2048px 白底图（33枚系列）会显示白色方块且体积 60MB+ → 用 normalized2 的 512px 透明 ARGB 版（38 张全量接入）
6. **hvigor 6.x 明文签名口令报「length less than 32」** → 只认 DevEco 加密格式口令 → 改用 hap-sign-tool 直签（见第四节），勿再尝试把明文口令写进 build-profile.json5
7. **hvigorw 报 DEVECO_SDK_HOME invalid / spawn java ENOENT** → CLI 环境缺 SDK 与 Java；且 hvigor 守护进程缓存旧环境 → 设好 env 后 `hvigorw --stop-daemon` 再执行
8. **AGC「软件包解析失败」**（v1.0.6 首次上传）→ .app 为 DevEco 自动 debug 证书签名 → 发布证书重签后通过
9. **git 根提交信息含旧名「银痕」需修改** → 已发布历史只能重写：`checkout --detach <root>` + `commit --amend` + `rebase --onto <newroot> <oldroot> main`，tag 原都指向根提交，逐个 `-f` 重建后强推；GitHub Release 资产与正文不受影响
10. **GitHub 页面仍显示旧描述/旧信息** → 浏览器缓存 → Ctrl+F5 强刷；仓库描述用 `gh repo edit --description` 维护
11. **包体积膨胀**：hap 由 1.9MB 涨至 18.9MB → 39 张 512px 徽章共 16.6MB；界面最大展示 72vp（≈234px@3.25x），如需瘦身可压到 256px（约降至 1/4），**暂未做，用户未拍板**
12. **ArkTS 严格模式高频报错** → 状态装饰器 V1/V2 不可混用（@Component/@State vs @ComponentV2/@Local）、对象字面量需显式类型、禁 any/`as`/动态属性访问 → 改动后先 `arkts_check` 再 build，能省一轮全量编译排错
13. **PowerShell 下 rg 等 unix 工具不可用** → 用内置 grep/glob 工具替代
